# Unit 35: LiteLLM model proxy and virtual keys

## Goal

Vendor keys live only in the model proxy; each agent phase receives a
per-phase virtual key with `max_budget = phase_cap_usd` and a duration of
its timeout, revoked at `phase_end`; the proxy's spend is the meter; the
task environment carries only the virtual key and the proxy base URL (PRD
§Capability 3 · Limits, §Capability 5 · Cost; TRD §3.4, §6.3). The proxy
runs on Docker Desktop on this PC (user decision, 2026-10-24).

## Design

Terminal only. `factory proxy up` starts LiteLLM and its Postgres from
`deploy/docker-compose.proxy.yml`; `factory proxy status` checks it. With
`FACTORY_PROXY_URL` and `FACTORY_PROXY_MASTER_KEY` set, every agent phase
row carries `virtual_key_id`, the `agent_start` event names it, and the
phase cost comes from the proxy.

## Implementation

### deploy/

- `litellm/config.yaml`: generated by `litellm_config(roster)` from the
  shipped roster: one `model_name` per roster model id routed to
  `anthropic/...` or `openai/...` with the vendor key from the proxy's
  environment; master key and database URL from the environment.
- `docker-compose.proxy.yml`: `litellm` (`ghcr.io/berriai/litellm`,
  port 4000 on loopback, the config mounted read-only) and `litellm-db`
  (Postgres 16, required for virtual keys).

### orchestrator/budget/proxy.py

- `ProxyAdmin(base_url, master_key)`: `health`, `create_key(task_id,
  phase_id, role, max_budget_usd, duration_s, models)` → `VirtualKey(key,
  key_id)` where `key_id` is the proxy's hashed token, never the secret;
  `key_info(key)` → spend, max budget, expiry; `delete_key(key)`;
  `litellm_config(roster)`.

### orchestrator/budget/keys.py

- `PhaseKeys(admin)`: `issue(...)` → `IssuedKey(env, key, key_id,
  max_budget_usd)`; without a proxy the env is the phase 1 pass-through.
  `settle(issued, result)` reads the key's spend, revokes the key, replaces
  the harness cost with the proxy spend, and rewrites a failed result at
  the cap into `error_max_budget_usd`, which the phases already turn into
  a `budget_stop` and a `budget` block.
- `agent_env_for(settings, harness, key, proxy_url, phase_id)`: the base
  allow-list plus `FACTORY_PHASE_ID`, the proxy URL and the virtual key as
  `ANTHROPIC_*` for Claude Code or `OPENAI_*`/`CODEX_API_KEY` for Codex,
  `CODEX_HOME` under the data directory. No `os.environ` read beyond the
  base allow-list.

### Phases, deps, service, settings, CLI

- The three agent phases issue a key after the phase row starts, record
  `virtual_key_id`, run with the issued env, and settle before accounting.
- `BuildDeps.keys` and `RunnerDeps.keys`; `build_service` builds the admin
  from settings and refuses to start when the proxy is configured but
  unreachable (fail-closed, TRD §6.3).
- `Settings.proxy_url`, `Settings.proxy_master_key`; `factory proxy
  up|down|status`.

## Dependencies

- Docker Desktop (installed) for the real proxy; the unit tests use a fake
  LiteLLM over an httpx transport; the container test is opt-in with
  `FACTORY_DOCKER_TESTS=1`.

## Verify when done

- [ ] Create, read spend and revoke against the fake proxy; wrong master
      key is a `ProxyError`
- [ ] The issued env holds the virtual key and the proxy URL and no vendor
      key even when the process environment has them; Codex gets
      `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `CODEX_API_KEY`, `CODEX_HOME`
- [ ] Settle replaces the cost with the proxy spend and revokes; a failed
      phase at the cap becomes `error_max_budget_usd`
- [ ] A build with a proxy records `virtual_key_id` on the phase row and in
      `agent_start`, the fake harness receives the virtual key, the key is
      revoked, and the task's spend is the proxy's figure
- [ ] `deploy/litellm/config.yaml` equals `litellm_config(shipped roster)`;
      the compose file mounts it and exposes 4000 on loopback only
- [ ] The four quality commands pass; the container test passes when run
      with `FACTORY_DOCKER_TESTS=1`
